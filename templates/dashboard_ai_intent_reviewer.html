What This Workflow Is

Intent Understanding

Natural-language text is treated as a proposal to classify and review, not as permission to run a task.

Safety First

Report-only examples are allowed for review, while live-capable, SSH, device-changing, and ambiguous requests are blocked by default.

Reviewer Evidence

Day57-Day76 docs and optional generated JSON/HTML reports show how the workflow makes allowed and blocked decisions visible.

No Runtime Execution

No mapped task is delegated from this page. The dashboard only presents committed documentation and expected report paths.

  1. Read Day57 to see how static text maps to a proposed task without running it.
  2. Read Day58 to confirm the safety review gate and blocked-by-default policy.
  3. Read Day59 to review the allowed, blocked, and clarification-required policy matrix.
  4. Read or generate Day60 to inspect the end-to-end walkthrough report.
  5. Read Day62 to compare sample intents against the expected reviewer decisions.
  6. Read Day63 to trace each AI intent review concept back to Day57-Day62 evidence.
  7. Read Day64 to follow the reviewer acceptance steps, validation commands, and safety boundary confirmation.
  8. Read Day65 to review the final acceptance summary and sign-off package before the offline mock runtime skeleton.
  9. Read Day66 to inspect the fixed offline mock runtime skeleton and confirm live execution remains disallowed.
  10. Read Day67 to inspect the fixed runtime output contract and safety invariant validation layer.
  11. Read Day68 to confirm reviewer-visible report quality, evidence traceability, contract validation proof, and no-execution evidence.
  12. Read Day69 to drill into each offline mock scenario from the dashboard without submitting, executing, or delegating anything.
  13. Read Day70 to confirm the offline mock runtime phase exit decision and AI runtime readiness gate before any controlled Day71+ prototype planning.
  14. Read Day71 to review the controlled future AI runtime entry design, accepted input fields, expected output fields, safety gate order, and still-blocked surfaces.
  15. Read Day72 to review the controlled input contract validator that checks payload shape and blocked intent text before any future runtime decision path.
  16. Read Day73 to review deterministic mock decision labels produced after Day72 validation without executing mapped tasks.
  17. Read Day74 to review deterministic dry-run plan previews built from Day73 decisions without executing mapped tasks.
  18. Read Day75 to review deterministic record-only approval envelopes built from Day74 plans without unlocking execution.
  19. Read Day76 to review the deterministic audit trail that links Day73 decisions, Day74 plans, and Day75 approval envelopes into evidence packages without unlocking execution.
  20. Use Reports for generated local evidence when available.

Day72 Controlled AI Runtime Input Contract Validator

Day72 adds deterministic input contract validation for future controlled AI runtime requests. It validates structured intent payloads only, blocks unsafe intent text and unsafe declared fields, and returns reviewer-facing validation results before any future runtime decision path can inspect the request.

  • Required fields include user_intent_text, requested_operation_type, target_scope, safety_level, evidence_required, reviewer_required, and execution_allowed.
  • Safe inputs may validate, but execution_allowed remains false.
  • Unsafe examples such as SSH, firewall changes, VRRP priority changes, device reboot, OpenAI/API connection, voice mode, mapped task execution, subprocess, socket, requests, API keys, secrets, or device access are blocked.
  • Reviewer-required inputs return reviewer_required=true and use a report-only next safe step.
Open Day72 validator doc Open Day72 roadmap

Day73 Mock AI Decision Pipeline

Day73 adds a deterministic mock decision stage after the Day72 validator. It consumes fixed documentation-only, report-only, ambiguous, live-action, and invalid-input scenarios, then records reviewer-visible decision labels without calling an AI provider or executing anything.

  • Decision labels include DOCUMENTATION_ONLY, REPORT_ONLY, REVIEW_REQUIRED, BLOCKED_LIVE_ACTION, and INVALID_INPUT_BLOCKED.
  • allowed_to_execute remains false for every mock decision record.
  • Live device or network action requests are blocked, invalid inputs are blocked, and ambiguous inputs require manual review.
  • Documentation/report-only inputs may become reviewer-ready evidence, but they still do not execute mapped tasks.

Day74 Controlled Dry-run Plan Builder

Day74 converts deterministic Day73 mock decision records into reviewer-friendly dry-run plan previews. A dry-run plan is a structured inspection artifact only; it is not an execution flow and cannot unlock execution.

  • Plan statuses include DRY_RUN_READY, REVIEW_REQUIRED, BLOCKED, and INVALID_INPUT_BLOCKED.
  • allowed_to_execute remains false for every dry-run plan.
  • dry_run_only remains true for every dry-run plan.
  • Documentation-only and report-only decisions may produce preview steps, while live-action and invalid-input decisions remain blocked.
  • Reviewer-required plans include reviewer checks and stop before any mapped task, command, API call, SSH, device access, or configuration change.
