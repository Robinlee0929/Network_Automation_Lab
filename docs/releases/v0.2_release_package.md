# v0.2 Release Package

Day41 packages the Day31-Day40 HA / VRRP milestone into a reviewer-ready v0.2 release package. This is a report-only and documentation-only release packaging step. It does not run live tests, open SSH sessions, connect to routers, switches, firewalls, or physical devices, change device configuration, implement voice or AI features, or create a `v0.2` git tag.

The `v0.2` tag is intentionally deferred to Day42.

## Release Purpose

v0.2 extends the Network Automation Lab portfolio from single-device and VPN evidence into a safety-first HA / VRRP evidence package. The release goal is to show that network automation work can be structured as a traceable platform with:

- Clear topology intent.
- Explicit safety levels.
- Read-only and dry-run boundaries before live action.
- Evidence-driven reports.
- Dashboard and report-index visibility.
- A repeatable portfolio demo handoff path.

## VRRP / HA Topology Summary

The v0.2 topology centers on two MikroTik hEX S 2025 routers and a Cisco switch lab environment:

- `Hex-s-2025-lab01` is the primary / higher-priority master candidate.
- `Hex-s-2025-lab02` is the backup candidate.
- VRID is `88`.
- VRRP interface is `vrrp-lan` on parent interface `bridge`.
- Virtual gateway intent is VIP `192.168.88.99/32`.
- Physical LAN bridge IPs remain separate from the VIP.

The topology is documented for portfolio review and safety reasoning. Day41 does not prove new topology behavior; it packages existing Day31-Day40 evidence.

## Safety Model Summary

Day41 preserves the existing safety boundary:

| Safety level | Meaning in v0.2 |
| --- | --- |
| report-only | Reads local docs/metadata/reports and writes local summaries only. |
| read-only | May collect live state without changing device configuration, only in tasks explicitly marked read-only. |
| dry-run | Renders planned commands or validations as local preview output only. |
| guarded-live | Requires explicit guardrails before delegated live validation. |
| controlled failover | Uses a manual external failure trigger and read-only observation for HA evidence. |

Day41 itself is `report-only`.

Day41 safety assertions:

- No live network test.
- No SSH.
- No MikroTik, Cisco, firewall, NAT, IP, VRRP, interface, reboot, reset, or topology setting change.
- No voice feature implementation.
- No AI report assistant implementation.
- No `v0.2` git tag creation.

## Dashboard / Report Integration Summary

v0.2 evidence is meant to be reviewable through local artifacts:

- `python network_lab.py --list-tasks --verbose` shows task safety metadata.
- `python network_lab.py --task report-index` generates `reports/report_index.html`.
- Dashboard `/reports` surfaces available local JSON/HTML evidence.
- Latest lab overview includes HA / VRRP evidence discovery metadata.
- Day39 and Day40 reports provide pre-release dashboard and demo readiness context.
- Day41 adds a release packaging report path for the same local discovery flow.

Generated files under `reports/` are ignored by `.gitignore`, so committed docs and runner metadata remain the durable source of truth.
