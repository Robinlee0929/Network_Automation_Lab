# v0.2 Demo Handoff Guide

This guide is the recommended interview/demo order for the v0.2 HA / VRRP package. It is documentation-only. It does not require live lab access, SSH, device credentials, device configuration changes, voice features, AI features, or a `v0.2` tag.

## Recommended Demo Order

1. Open `README.md` and explain the project goal.
2. Show the topology and HA / VRRP safety model.
3. Show the Unified Runner task catalog.
4. Show the Day31-Day40 package summary.
5. Show dashboard `/reports`.
6. Show the latest lab overview and report index.
7. Show Day35 controlled failover evidence.
8. Show Day39 dashboard integration evidence.
9. Show Day40 demo readiness review.
10. Explain safety levels.
11. Explain known limitations.
12. Explain v3.0 Voice + AI roadmap as future direction only.

## Talk Track

Start with the portfolio framing:

> This is a safety-first network automation lab. v0.2 packages the HA / VRRP milestone as traceable evidence, not as uncontrolled live automation.

Then point to the topology:

- `docs/roadmap/ha_vrrp_topology_plan.md`
- `docs/roadmap/ha_vrrp_safety_model.md`
- `docs/assets/mikrotik-cisco-lab-topology-v0.2-final.png`

Then show the runner catalog:

```powershell
python network_lab.py --list-tasks --verbose
```

Call out that Day41 is report-only / documentation-only.

## Safety Levels

| Safety level | Demo explanation |
| --- | --- |
| report-only | Reads local docs, metadata, and generated reports only. |
| read-only | May collect live state, but does not change device configuration. |
| dry-run | Shows planned commands as text only and does not connect to devices. |
| guarded-live | Requires explicit operator approval and safety guardrails. |
| controlled failover | Uses a manual external trigger and read-only observation. |

Day41 is report-only.

## Known Limitations

- Some optional reports may be missing.
- Generated reports under `reports/` may be ignored by `.gitignore`.
- Day41 does not create a `v0.2` tag.
- Day41 does not prove new live behavior.
- Day41 only packages existing Day31-Day40 evidence.
- Voice + AI is future roadmap only, not implemented in v0.2.
- The controlled failover trigger is manual and external.
- The demo depends on local generated evidence being present when screenshots or HTML report views are needed.

## v3.0 Roadmap Note

Voice + AI Network Test Assistant / AI-assisted Network Test Orchestration is a future direction only. In this demo, present it as a roadmap idea for later work, not as a v0.2 capability.

Day42 remains the next release step for `v0.2` tag preparation.
