# v0.1 Release Notes

## Release Summary

Network Automation Lab v0.1 packages the Day1-Day29 lab automation, documentation-review, and release tag preparation work into a portfolio-ready release. The release focuses on repeatable network validation, safety-labelled runner workflows, readable JSON/HTML evidence, and a clear reviewer path.

## Included Scope

- MikroTik RouterOS baseline, reset setup, post-setup, multi-device baseline, WireGuard validation, and performance workflows.
- Cisco IOS switch topology validation.
- Lab-level topology and report summaries.
- Local Flask dashboard for report viewing and safe allowlisted command examples.
- Unified runner task catalog with report-only, read-only, guarded-live, dry-run, and disabled safety boundaries.
- Portfolio evidence index, demo flow, Day25 RC validation evidence, Day26 v0.1 documentation polish, Day28 final evidence review, and Day29 release tag preparation.

## Safety Posture

The v0.1 Day26-Day29 package is documentation-only. It adds and aligns release notes, demo scripts, evidence navigation, portfolio checklist wording, and release tag preparation notes; it does not add runner tasks, product features, report generators, live workflow execution, or generated release package artifacts.

Live validation remains behind the existing read-only, dry-run, guarded-live, or disabled runner controls. v0.1 documentation does not read `config.json`, exported WireGuard `.conf` files, SSH passwords, private keys, or local secrets.

The safe command runner remains allowlist-based and does not accept arbitrary shell command input. Generated `reports/`, `exports/`, real configs, credentials, passwords, private keys, WireGuard `.conf` files, caches, and environment-specific files are not part of the committed v0.1 evidence package.

## Known Notes

- Report index output may show WARN when optional local evidence has not been regenerated.
- Generated `reports/` output is intentionally not committed.
- v0.1 is a portfolio release package, not a claim that every optional live lab report is always present on a fresh checkout.
- Real device execution depends on the local lab setup, network reachability, credentials, and explicit user authorization.
- Live VPN activation, HA, VRRP, failover, and additional device-control logic are future work, not implemented v0.1 release claims.
