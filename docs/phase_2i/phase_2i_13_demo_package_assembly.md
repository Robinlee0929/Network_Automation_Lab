## Purpose

The purpose of this package is to make the Phase 2I demo easy to scan, easy to present, and safe to review.

Phase 2I-06 explains how to talk through the project. Phase 2I-09 explains how to demonstrate AI-assisted explanation without implying AI control. Phase 2I-13 places those two materials into a package-level reading order and names the safety boundary that must stay visible during the demo.

## Package Contents

The Phase 2I demo package contains these committed documentation artifacts:

- `docs/phase_2i/phase_2i_06_demo_interview_script.md`
- `docs/phase_2i/phase_2i_09_demo_ai_safe_workflow.md`
- `docs/phase_2i/phase_2i_13_demo_package_assembly.md`

The package may also point reviewers to existing static dashboard wording, README phase navigation, and report-index output when those artifacts are already available through separately authorized safe validation.

The package does not create new runtime evidence. It does not discover files, regenerate reports, scrape dashboards, call external services, or inspect live infrastructure.

## Recommended Review Order

Reviewers should read the package in this order:

1. Start with this Phase 2I-13 package assembly document.
2. Read Phase 2I-06 to understand the safe interview script and presenter wording.
3. Read Phase 2I-09 to understand how AI-assisted explanation stays attached to committed evidence.
4. Inspect the README Phase 2I navigation entry to confirm the documented phase sequence.
5. Optionally inspect existing static dashboard or report-index evidence if it has already been generated by separate safe validation.

This order keeps the safety boundary visible before the reviewer evaluates any demo narrative.

## Demo Walkthrough

The recommended walkthrough is:

1. Open with the Phase 2I-06 statement that the project is a safe, local, deterministic network automation lab.
2. Explain that the dashboard and documentation are evidence surfaces, not control surfaces.
3. Use Phase 2I-06 to describe the project value in plain language.
4. Use Phase 2I-09 to show the safe AI role: explaining committed evidence, summarizing static wording, and clarifying safety boundaries.
5. State explicitly that AI is not a controller, runner, adapter, broker, scheduler, worker, or autonomous agent.
6. Close by pointing to Phase 2I-18 as the future final demo readiness review, not as work started by this package.

The walkthrough is presenter guidance only. It does not run any command, job, model, provider, device session, or background process.

## How Phase 2I-06 And Phase 2I-09 Fit Together

Phase 2I-06 is the interview script. It answers, "How should the project be introduced safely?"

Phase 2I-09 is the AI safe workflow. It answers, "How can AI-assisted explanation be demonstrated without becoming automation?"

Phase 2I-13 is the package assembly layer. It answers, "In what order should a reviewer read and present those materials?"

This package does not rewrite Phase 2I-06 or Phase 2I-09. It preserves their meaning and makes their relationship easier to review.
